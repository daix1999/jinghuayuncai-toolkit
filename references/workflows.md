# 详细工作流

> 本文件承载三大能力的完整工作流、检查点、异常处理、输入规范与案例。
> SKILL.md 只保留速查，执行具体任务时按需查阅本节。

## 能力一：名单电话填充（反向匹配）

### 触发场景

- 用户提供一个京华云采供应商名单（xlsx），指出电话列有空白
- 要求"填充电话""补全联系方式""把空号补上"
- 名单可能是"云采代翔""近两年下单经销商"或其他云采供应商清单

### 一键入口（推荐先试）

若用户只想快速补电话，优先用 `scripts/run.py` 一键完成「找空号 → API 查询 → 填充」：

```bash
python scripts/run.py 名单.xlsx --name-col 供应商名称 --phone-col 联系电话
```

- 自动识别空号、官网 API 查询、填充并输出 `原名_已填充.xlsx`
- API 查不到的自动标注「未匹配」并列出清单，供后续公开搜索补漏
- 只有「未匹配」的公司才需要走完整工作流的公开搜索环节

### 工作流（完整版，含公开搜索）

**第一步：读懂名单，找空号**

1. 用 pandas 读取 xlsx，确认列结构（供应商名称列、电话列、备注列的确切位置）
2. 警惕多行表头：京华云采名单常有标题行 + 子表头行，数据可能从第 3 行才真正开始
3. 电话为空判断：`isna()` 或值为空字符串 / `'nan'` / `'None'`
4. 提取空号公司的名单，存成 JSON 数组 `["公司A", "公司B", ...]`

**第二步：通过京华云采官网 API 查询（零成本，最优先）—— 快路径：按公司名反查**

**省时关键**（2026-08-20 实测）：`querySkuAgentListFromEs` 支持 `shopName` 参数，**不带 skuId 只带 shopName 就能按公司名定向反查**，一家公司 1-2 次请求直接拿电话，**不用遍历全部商品**（原方案 500+ 次请求）。优先用 `scripts/query_suppliers_by_name.py`：

```bash
python scripts/query_suppliers_by_name.py <供应商名单.json> --out api_match_result.json
```

- 一家公司 1 次请求（第 1 页即含 agentPhone），命中率极高；品牌方（联想官方等）命中 0 条属正常
- 快路径未命中的公司，才用 `scripts/query_suppliers_by_api.py` 遍历商品兜底（旧方案）：
  ```bash
  python scripts/query_suppliers_by_api.py <未命中名单.json> --categories 台,笔,服,印 --out api_full_result.json
  ```
- 命中 → 电话来源标注「京华云采API(反查)」或「京华云采API」，绿色
- 未命中 → 进入第三步公开搜索

**第三步：公开搜索 —— ⚠️ 默认走风鸟批量，不逐家 WebSearch**

**省 token 关键**：未命中公司 ≥5 家时，**默认调用 `riskbird-cominfo-batch` 技能走风鸟批量查询**，不要用 WebSearch 逐家搜（每家一次搜索 = 大量 token）。只有 <5 家零星的才 WebSearch。

- **批量优先（风鸟，默认）**：调用 `riskbird-cominfo-batch` 技能，通过风鸟（riskbird.com）CDP 浏览器自动化批量提取电话/邮箱/地址/法人/注册资本，无需付费、无需 API Key。前置条件：用户 Chrome 已打开风鸟、CDP Proxy 运行（localhost:3456）、名单为 JSON 数组
- **零星补漏（WebSearch，仅 <5 家）**：搜索词 `"公司全名" 电话 联系方式`、`"公司全名" 中标 OR 成交 供应商`
- 渠道优先级：风鸟（批量）→ 黄页类 → 企业征信（企查查/天眼查/启信宝）→ 政府采购网（能拿真实对接人）→ 官网
- 每条结果提取：电话号码 + 法人/联系人 + 注册资本（用于身份备注）
- 号码打码时用多来源交叉验证；无法确认时标注"未找到"，绝不填猜测号码

**第四步：填充副本（不覆盖原文件）**

合并 API 结果和公开搜索结果，构造映射 JSON：
```json
{"公司名": {"phone": "号码", "source": "京华云采API 或 公开搜索-天眼查", "contact": "法人:XXX, 注册资本XXX万"}}
```
再用 `scripts/fill_phones.py` 填充：

```bash
python scripts/fill_phones.py <输入xlsx> <映射json> --name-col A --phone-col D --remark-col F
```

- 默认输出到 `原名_已填充.xlsx`，原文件不动
- 脚本自动新增两列：`电话来源` 和 `可能联系人及身份`
- 颜色标注：绿色 = 京华云采API，黄色 = 公开搜索，橙色 = 未找到

**第五步：交付并说明**

- 用 present_files 展示填充后的副本
- 汇总：共空号 N 家，填充 M 家，未找到 K 家
- 点出高价值供应商（本身就在做联想、注册资本大、是政采定点供应商等）

## 能力二：经销商爬取（正向维度）

### 触发场景

- "查一下京华云采上联想所有产品的经销商"
- "台式机品类下都有哪些经销商"
- "开天M70d 这款产品有哪些经销商在卖"
- 想按品牌/品类/产品维度圈定一批经销商，做渠道拓展

### 工作流

用 `scripts/crawl_dealers.py` 正向爬取：

```bash
# 指定品类下所有产品的经销商
python scripts/crawl_dealers.py --category 台 --out 台式机经销商.xlsx

# 指定品牌下所有产品的经销商
python scripts/crawl_dealers.py --brand 联想 --out 联想经销商.xlsx

# 指定产品（关键词）的经销商
python scripts/crawl_dealers.py --product 开天M70d --out 开天M70d经销商.xlsx

# 组合：台式品类 + 联想品牌
python scripts/crawl_dealers.py --category 台 --brand 联想 --out 台式联想经销商.xlsx
```

- `--category`：品类键（台/笔/服/印），逗号分隔，默认全部
- `--brand`：品牌名（如 联想），模糊包含匹配，逗号分隔
- `--product`：产品关键词（如 开天M70d、X5z），按 skuName 包含匹配
- 三个维度可任意组合，也可单独使用

**统一输出格式**（无论哪种维度，都输出这张表）：

| 品类 | 品牌 | 产品 | 经销商名称 | 销售电话 |
|------|------|------|-----------|---------|

- 同一经销商代理多款产品时，自动聚合到一行（品类/品牌/产品用"、"分隔，电话用" / "分隔）
- 输出 Excel，直接可用于渠道拓展跟进

## 能力三：销售记录获取 + 数据分析

### 触发场景

- "查一下联想开天M70d 的销售记录"
- "台式机品类最近成交了多少、谁采购的"
- "某型号在政府采购里卖了多少台、什么价"
- 想了解某品牌/型号的真实成交情况（采购单位、数量、单价），做竞品分析和报价参考

### 工作流：拉销售记录

用 `scripts/fetch_sale_records.py` 拉取：

```bash
# 指定型号的销售记录
python scripts/fetch_sale_records.py --product 开天M70d --out 开天M70d销售记录.xlsx

# 指定品牌的销售记录
python scripts/fetch_sale_records.py --brand 联想 --out 联想销售记录.xlsx

# 指定品类的销售记录
python scripts/fetch_sale_records.py --category 台 --out 台式机销售记录.xlsx
```

- 先通过商品搜索接口拿到目标商品的 `skuId` 列表
- 再对每个 `skuId` 调销售记录接口（`shop-bjzc.zhongcy.com` 的 `querySkuSaleRecord`，GET 方法）
- 汇总输出统一表

**统一输出格式**：

| 品类 | 品牌 | 型号 | 采购单位 | 采购数量 | 采购单价(元) | 供应商 | 成交时间 |
|------|------|------|---------|---------|-------------|--------|---------|

- 销售记录接口字段名已实测对齐：`organizeName`(采购单位)、`shopName`(供应商)、`skuNum`(数量)、`sellPrice`(单价)、`orderTime`(成交时间)，结果数组在 `data.result`，分页用 `data.totalPageCount`

### 工作流：数据分析（进阶）

拉完销售记录后，用 `scripts/analyze_sales.py` 做多维分析，**每个分析 Sheet = 「汇总表 + 📌关键订单明细 + 📌分析说明」**，订单明细具体到采购单位/供应商/型号/配置/数量/单价/时间：

```bash
python scripts/analyze_sales.py 开天M70d销售记录.xlsx --out 开天M70d分析报告.xlsx
```

输出 12 个 Sheet：

| Sheet | 内容 |
|-------|------|
| 销售明细 | 原始成交数据（品牌/型号/**配置**/单位/供应商/数量/单价/时间） |
| **整体分析报告** | 文字为主的总结报告：概览/品牌/买方/供应商/价格/趋势/结论建议 |
| 品牌对比分析 | 不同品牌之间对比（销量/金额/客户数 + 说明） |
| 型号分析 | **品牌 × 型号 × 配置**（销量/金额/均价/价格区间 + 说明） |
| **配置价格稳定性** | 同型号同配置价格是否稳定；**明显波动项单独标出**（议价信号） |
| 单位类型分布 | 政府/学校/医院/企业/其他（+ 说明，标出渗透率低的空白类型） |
| 多次往来 | 同一单位 × 同一供应商多次成交（+ 说明） |
| 供应商占比 | 各供应商占比 + TOP3 集中度（+ 说明） |
| 月度销售趋势 | 按月销量/金额 + 环比（+ 说明） |
| TOP采购单位 | 采购额排行（+ 说明） |
| 价格分析 | 均价/最高/最低/中位数（+ 说明） |
| 采购频次 | 1次/2次/3-4次/5次+ 分组（+ 说明） |

> 💡 **价格分析要点**：同一型号会有不同配置（CPU/内存/硬盘/显卡/显示器），价格差异多由配置不同导致。脚本自动把型号拆分为「型号 + 配置」，价格按配置分组对比——同配置价格稳定属正常；**同配置下价格仍明显波动（>100 元或 >2%）则单独标注，并在明细里贴出最低价 vs 最高价订单**（谁买贵了、谁买便宜了一眼可见），那是议价空间信号。

## 关键检查点（执行前务必确认）

1. **批量爬取/拉取前**：先确认品类、品牌、产品范围，避免全量误爬导致耗时过长（几分钟到几十分钟）
2. **填充副本前**：展示命中结果概要（命中 N 家、未命中 M 家），用户确认后再写文件
3. **公开搜索前**：未命中公司 ≥5 家时，确认是否用风鸟批量（需用户 Chrome 已打开风鸟 + CDP Proxy 运行）
4. **交付前**：汇总空号 / 填充 / 未找到数量，点出高价值供应商

## 边界条件与异常处理

| 场景 | 处理动作 |
|------|---------|
| 官网 API 超时 / SSL 握手失败 | 脚本已内置 `trust_env=False` 绕过本地代理直连；仍失败则提示用户检查网络，本次降级为纯公开搜索 |
| 商品搜索返回空 | 换关键词 / 品类重试一次；仍空则如实告知"该维度暂无数据"，不硬造结果 |
| 销售记录无成交 | 如实告知"该机型暂无成交记录"，不视为错误 |
| 名单列号 / 列名不确定 | 脚本支持列名或列号（`--name-col 供应商名称` 或 `A`）；多行表头自动跳过标题行定位真实表头 |
| 同名公司 | 按全称精确匹配；模糊命中需核对统一社会信用代码或注册地址 |
| 风鸟技能不可用 | 未安装或额度耗尽时自动降级 WebSearch，主流程不受影响 |
| 号码打码 / 无法确认 | 标注"未找到"，绝不填猜测号码——错号比空号更伤信任 |
| API 限频 / pageSize 超限 | 请求间 sleep 0.15~0.3 秒，pageSize 固定 100（超限报错）；打印机 5 个子类 cid 已内置展开 |

## 数据可信度原则

1. **副本操作**：只输出 `原名_已填充.xlsx`，绝不覆盖原始文件
2. **来源必标**：每个电话标注来源（京华云采API / 公开搜索-某渠道 / 未找到），便于判断可信度
3. **联系人备注**：法人 / 对接人 / 注册资本写进独立列，是后续沟通的弹药
4. **优先官网号码**：官网 API 拿到的电话最新、最可信；公开搜索的号码打前先核实

## 输入格式规范

### Excel 名单（名单补电话用）

- 至少包含「供应商名称」列和「联系电话」列
- 列名可自定义；填充时用 `--name-col` / `--phone-col` 指定**列名**（如 `供应商名称`）或**列号**（如 `A`），无需手动数列号
- 支持多行表头，脚本自动跳过标题行、定位真实表头

### 名单 JSON（官网 API 查询用）

```json
["公司A", "公司B", "公司C"]
```

### 映射 JSON（填充用）

```json
{"公司A": {"phone": "13800000000", "source": "京华云采API", "contact": "法人:张三, 注册资本1000万"}}
```

## 能力边界（使用前须知）

1. **依赖官网公开接口**：电话 / 销售记录依赖京华云采接口，若官网改版或限频，接口可能失效，需按 `references/api_docs.md` 重新抓包更新端点
2. **仅覆盖电脑 / 服务器 / 打印机品类**：台式机、笔记本、服务器、打印机；其他品类（家具 / 办公用品）API 查不到，走公开搜索
3. **大批量耗时**：按品牌 / 品类全量爬取需遍历多款商品，几分钟到几十分钟属正常，建议分批
4. **电话非 100% 可得**：部分供应商只做非电脑品类或已更名，API 与公开搜索都查不到，如实标注"未找到"
5. **成交数据为公开信息**：仅作参考，使用前自行核实

## 使用案例（端到端）

**场景：领导给了 100 家供应商名单，电话列 34 家空白，需补全。**

1. 读名单提取 34 家空号公司，存 `companies.json`
2. 官网 API 反查（快）：`python scripts/query_suppliers_by_name.py companies.json --out api_match.json` → 命中 28 家；未命中 6 家再用 `query_suppliers_by_api.py` 兜底
3. 公开搜索补漏：仍未命中的公司（≥5 家），**默认调 `riskbird-cominfo-batch` 批量查**（不逐家 WebSearch），得 phone / source / contact
4. 合并映射 `mapping.json`
5. 填充副本：`python scripts/fill_phones.py 名单.xlsx mapping.json --name-col 供应商名称 --phone-col 联系电话` → 输出 `名单_已填充.xlsx`
6. 交付：展示副本，汇总「填充 N 家 / 未找到 K 家」，点出高价值供应商

## 能力四：经销商画像（代理商品 → 销售记录 → 客户）

### 触发场景

- "查一下 XX 公司的全景数据"
- "这家经销商代理了什么品牌、客户是谁"
- 想知道某经销商真实业务结构（电脑 vs 耗材）、成交规模、服务哪些单位

### 数据链路（2026-08-20 打通）

```
反查(shopName) → 代理商品 skuId 列表（含电话/销售区域/供货价/库存）
              → 商品索引 sku_index.json 补品牌/商品名
              → 每个 skuId 查销售记录 → 归集 shopName==该经销商 的成交 → 客户清单
```

### 使用步骤

**第一步：建商品索引（一次即可，之后复用）**

```bash
python scripts/build_sku_index.py --out sku_index.json --all
```

- 全品类抓取（不带 cid 全量，约 1 万商品），几分钟
- 之后增量更新（再跑一次自动只抓新的）；`--refresh` 强制全量
- 索引里有 skuId → 商品名/品牌/cid 映射，是画像匹配商品名的依据

**第二步：生成经销商画像**

```bash
python scripts/dealer_profile.py "北京宏鹏电脑有限公司" --index sku_index.json --out 画像.xlsx
```

参数：
- `--max-skus N`：最多分析的代理商品数（默认 100，0=全部；代理商品多的经销商建议调大）
- `--quiet`：只打印摘要

**输出 Excel（6 个 Sheet）**：

| Sheet | 内容 |
|-------|------|
| 经销商概览 | 电话/销售区域/代理商品数/成交商品数/零成交数/总销量/总金额/客户数 |
| 品牌分布 | 代理商品的品牌分布（看真实业务结构：电脑 vs 耗材） |
| 代理商品清单 | skuId/商品名/品牌/供货价/库存/有无成交 |
| 成交记录 | 该经销商实际卖出的每笔订单（客户/商品/数量/单价/时间） |
| 客户汇总 | 客户 × 次数/数量/金额排行 |
| 零成交商品 | 代理了但没卖出去的商品（潜在机会） |

### 关键要点

1. **归集口径**：销售记录里的 `shopName` 才是"实际卖出方"，反查的 `agentName` 是"代理方"。画像只归集 `shopName == 该经销商` 的成交，才是它自己卖的客户
2. **业务结构识别**：京华云采经销商普遍"电脑+耗材"混合代理（复印纸/硒鼓等），画像能一眼看出真实结构——纯电脑商 vs 耗材商
3. **索引未覆盖**：已下架商品或索引未抓到的标"未知商品"，属正常（在售电脑商品匹配率高）
4. **反查电话**：画像直接带出该经销商电话（agentPhone），可同时用于线索
